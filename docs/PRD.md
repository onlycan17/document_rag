# PRD: RAG 기반 공공기관 정보시스템 챗봇

본 문서는 현재 코드베이스(run_rag.py, app.py, src/*)를 역으로 분석해 정리한 요구사항 정의서입니다. 실 운용을 염두에 둔 목표/범위/지표를 명확히 합니다.

## 1. 제품 개요
- 목적: 공공기관 지침/문서를 기반으로 질문에 정확하고 친절한 한국어 답변을 제공하는 RAG(Retrieval-Augmented Generation, 용어(설명: 검색(Retrieval)으로 관련 자료를 모아 생성(Generation) 모델에 함께 주는 방식)) 챗봇.
- 대상 사용자: 정책/지침 문서를 빠르게 이해하고 싶은 실무자, 담당자, 신규 입사자.
- 주요 가치: 신속한 문서 탐색, 출처 기반의 신뢰성, 쉬운 설명.

## 2. 목표(Goals)
- 문서 업로드 후 자동 인덱싱(벡터화) 및 검색 가능.
- 한국어 특화 답변(쉬운 설명, 용어 풀이, 구조화된 결과).
- 답변은 `핵심 요약 → 상세 설명 → 참고 자료` 구조를 기본으로 유지하고, 목록/표 형식을 활용해 가독성을 높임.
- 스트리밍 응답(실시간 타이핑) 제공으로 빠른 피드백.
- 로컬/클라우드 LLM 교체 가능(OpenAI, Google, Anthropic, Local).
- 하이브리드 검색(벡터+키워드 BM25/TF‑IDF)과 MMR(용어(설명: 유사한 문서 중 다양성을 높여 겹치지 않게 고르는 방법)) 지원.

## 3. 비목표(Non‑Goals)
- 완전한 문서 관리 시스템(DMS) 기능(권한/버전 관리 등) 제공.
- 대규모 분산 인덱스 운영(단일 노드 기준 설계).

## 4. 사용자 시나리오
- 시나리오 A: 실무자 김씨는 `.pdf` 문서를 `data/documents/`에 넣고, `python run_rag.py` → 벡터 DB 구축 → 앱 실행 → 질문 입력 → 관련 출처와 함께 한국어 답변 확인.
- 시나리오 B: 네트워크 제한 환경에서 로컬 LLM(GGUF)로만 답변. `.env`로 모델/스레드/컨텍스트 크기 조정.
- 시나리오 C: 검색 품질이 낮을 때 하이브리드 검색/임계값 자동 조정으로 상위 결과 확보.

## 5. 주요 기능 범위
- 문서 로더: PDF(OCR 선택), Markdown/TXT 파싱 및 청크 분할.
- 임베딩: Upstage/OpenAI/HF 한국어 모델 선택, 배치 처리 및 재시도.
- 벡터 스토어: FAISS(기본)/Chroma, 하이브리드 검색, MMR, 임계값 동적 조정.
- RAG 체인: 대용량 컨텍스트 분할/요약/병렬 처리, 스트리밍/비스트리밍 답변.
- UI/CLI: Streamlit 앱, 통합 실행/설정/테스트 메뉴(run_rag.py).

## 6. 제약사항/가정
- Python 3.10+, 로컬 파일 시스템 기반 저장소(`vector_db/`, `processed_docs/`).
- `.env`에 최소 1개 LLM 키 필요(또는 로컬 LLM).
- 단일 머신 운영 가정(메모리/스레드/컨텍스트 한도는 설정으로 보호).

## 7. 성공 지표(메트릭)
- 답변 대기시간: P50 < 3초(스트리밍 시작 기준), P95 < 8초.
- 검색 정확도: 사용자가 “유용” 이상으로 평가하는 비율 > 80%.
- 실패율: 쿼리 처리 에러율 < 1%.
- 인덱싱 시간: 100문서(중형 PDF) 기준 10분 내.

## 8. 품질/운영 요구
- 로깅/오류 재시도(429 등 Rate Limit, 용어(설명: API 호출이 너무 많을 때 잠시 대기 후 재시도)).
- 환경 격리(venv), 설정 파일화(config.py), 안전 마진 적용.
- 테스트 스모크 제공(tests/test_simple.py 등).

## 9. 향후 확장
- 다국어 문서 혼합 처리 고도화(언어 감지/경량 번역).
- 문서 출처 하이라이팅/문단 단위 인용.
- 멀티 사용자 세션/권한.
