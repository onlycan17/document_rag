# 리팩토링 PRD

## 1. 목표
- 메인 앱과 서비스 모듈의 함수 길이를 줄여 단일 책임 원칙을 지키기.
- 이미지 처리, 스트리밍 응답 처리 로직을 모듈화하여 중복 제거.
- 전처리 모델 추상화에서 공통 로직을 통합해 유지보수성을 높이기.
- RAG 체인의 죽은 코드와 하드코딩된 값 정리.

## 2. 배경
- `app.py`의 `main` 함수가 130줄 이상으로 길고 예외 처리, UI 렌더링, 상태 갱신이 섞여 있습니다.
- `AppService.extract_images_from_content`가 130줄 이상이며 콘솔 출력(print) 기반으로 동작합니다.
- `ui/components/chat_interface.py`에서 이미지 추출을 다시 수행하여 코드가 중복됩니다.
- 전처리 모델(`LocalPreprocessingModel`, `APIPreprocessingModel`)이 문서 추출 과정을 반복 구현하고 있습니다.
- `RAGChain._get_model_max_tokens`에 실행되지 않는 코드가 존재합니다.

## 3. 범위
- Streamlit UI(`app.py`, `ui/components/chat_interface.py`)에서 상태 초기화, 사이드바 처리, 스트리밍 응답 처리 부분.
- 서비스 계층(`ui/services/app_service.py`)의 이미지 처리, 응답 포맷팅, 내보내기 로직.
- 전처리 모듈(`src/processing/`)의 모델 팩토리와 추상화 계층.
- RAG 체인(`src/rag/rag_chain.py`)의 컨텍스트/토큰 관련 보조 함수.

## 4. 비범위
- LLM 호출 방식 변경, 벡터 DB 구조 변경, UI 외형 변경은 하지 않습니다.
- 신규 기능 추가, 권한 관리 등은 이번 주제에서 제외합니다.

## 5. 요구사항
1. 함수 길이 30줄 초과 항목은 헬퍼 함수로 분리합니다.
2. 이미지 추출과 경로 해석을 전담하는 유틸 함수 세트를 마련하고, UI 레이어는 결과만 소비합니다.
3. 전처리 모델의 문서 추출 흐름을 공유 함수로 추출하고 DocumentProcessor 미사용 import 제거.
4. 죽은 코드 삭제 후, 모델 메타데이터는 LLMManager 헬퍼를 재사용하도록 연결합니다.
5. 모든 변경 후 `make fmt && make test && make lint`를 실행해 통과해야 합니다.

## 6. 성공 지표
- 30줄을 넘는 주요 함수 수가 현재 대비 50% 이상 감소.
- `AppService`와 `chat_interface` 사이의 중복 로직 감소(이미지 추출이 한 곳에서만 수행).
- 테스트 및 린트 명령이 모두 성공.

## 7. 타임라인
- Day 1: 문서화 및 상세 설계.
- Day 2: 서비스/유틸 분리 구현.
- Day 3: 전처리 모델 및 RAG 체인 정리 후 테스트.

## 8. 리스크
- 모듈 분리 시 세션 상태 공유 방식이 깨질 수 있음 → 단계별 테스트.
- 이미지 경로 처리 로직 축약 시 특정 엣지 케이스 누락 가능 → 기존 로깅 유지, 테스트 케이스 작성.
