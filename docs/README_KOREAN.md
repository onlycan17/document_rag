# 🇰🇷 RAG 기반 공공기관 정보시스템 챗봇 (상세 가이드)

이 문서는 프로젝트의 주요 기능, 사용법, 아키텍처 및 기술적 세부사항에 대한 포괄적인 안내를 제공합니다.

## ✨ 주요 기능

- 📄 **다양한 문서 형식 지원**: TXT, Markdown, PDF, DOCX 등 다양한 형식의 문서를 처리합니다.
- 🖼️ **멀티모달 처리 (NEW!)**: 문서 내의 텍스트뿐만 아니라 이미지도 분석하고 추출하여 답변에 활용합니다.
- 🧠 **지능형 이미지 추출**: AI 모델을 사용하여 문서 내 이미지의 내용을 분석하고, 관련성 높은 이미지만 선별적으로 저장합니다. (OpenRouter 연동)
- 🤖 **전처리/후처리 OpenRouter 선택**: PDF→MD 전처리(텍스트/멀티모달)와 MD 후처리에서 OpenAI/Google/Anthropic와 동일하게 OpenRouter를 선택할 수 있습니다.
- 🚀 **고성능 RAG 파이프라인**:
  - **다중 LLM 지원**: OpenAI(GPT), Google(Gemini), Anthropic(Claude), Upstage(Solar) 및 로컬 LLM을 손쉽게 전환하며 사용할 수 있습니다.
  - **실시간 스트리밍 답변**: ChatGPT와 같이 답변이 실시간으로 타이핑되어 사용자 경험을 향상시킵니다.
  - **동적 모델 설정**: 각 LLM 모델의 특성(최대 토큰, 컨텍스트 크기)을 동적으로 감지하고 최적의 설정으로 자동 조정합니다.
- 🔍 **고급 검색 및 컨텍스트 최적화**:
  - **쿼리 확장**: 사용자의 질문을 분석하여 관련 키워드를 자동으로 추가함으로써 검색 정확도를 높입니다.
  - **의미 기반 청킹**: 문서의 의미적 경계를 고려하여 청크를 분할함으로써 컨텍스트의 일관성을 유지합니다.
  - **품질 관리**: 벡터 DB에 저장되는 청크의 최소 크기를 보장하여 검색 결과의 품질을 향상시킵니다.
- 🔧 **통합 관리 도구**: `run_rag.py`를 통해 앱 실행, 벡터 DB 관리, 테스트 등을 한 곳에서 편리하게 수행할 수 있습니다.

## ⚙️ 설정 및 사용법

`streamlit run app.py` 또는 `python run_rag.py`로 앱을 실행한 후, 사이드바의 **"⚙️ 설정"** 메뉴에서 다양한 옵션을 조정할 수 있습니다.

### 📄 문서 관리

#### 1. 문서 업로드
- **문서 업로드**: TXT, MD, PDF, DOCX 파일을 드래그 앤 드롭하거나 선택하여 업로드합니다.
- **"문서 처리 및 저장"**: 버튼을 클릭하면 선택된 옵션에 따라 문서가 처리되어 벡터 데이터베이스에 저장됩니다.

#### 2. 처리 옵션

- **PDF OCR 사용**: 스캔된 PDF에서 텍스트를 추출합니다. (Tesseract 필요)
- **🤖 에이전트 모드 (고품질 처리)**: LLM을 활용해 문서의 구조와 문맥을 더 깊이 이해하여 처리합니다. (시간 소요)
- **✨ PDF 변환 시 텍스트 품질 자동 개선**: PDF에서 추출된 텍스트의 줄바꿈, 띄어쓰기 등을 자동으로 교정하여 가독성을 높입니다.

### 🤖 문서 전처리 (텍스트 및 이미지)

이 섹션은 문서 처리 시 사용할 AI 모델을 설정합니다.

- **문서 전처리 모델 선택**:
  - **로컬 모델**: 추가 비용 없이 빠르게 문서를 처리합니다. (기본값)
  - **OpenAI/Google/Anthropic**: 외부 API를 사용하여 더 높은 품질로 문서를 처리합니다. (API 키 필요)
- **🖼️ 멀티모달 전처리 활성화**: 체크 시, 텍스트와 이미지를 함께 분석하는 멀티모달 모델을 사용합니다. (외부 API 및 키 필요)
- **🧠 지능형 이미지 추출 활성화**: 문서 내 이미지를 AI로 분석하여 관련 있는 이미지만 저장하고, 텍스트가 포함된 이미지는 OCR로 변환합니다. (OpenRouter API 키 권장)

### 💾 벡터 DB 관리

- **저장된 문서 청크**: 현재 벡터 데이터베이스에 저장된 문서 청크의 총 개수를 표시합니다.
- **벡터 DB 초기화**: 저장된 모든 문서 청크를 삭제합니다.

### 🤖 LLM 모델 설정

챗봇의 답변을 생성할 LLM을 선택하고 설정합니다.

- **LLM 제공자 선택**: OpenAI, Google Gemini, Anthropic Claude, 로컬 LLM 등 원하는 제공자를 선택합니다.
- **모델 선택**: 선택한 제공자가 지원하는 모델 목록에서 특정 모델을 선택합니다. 각 모델의 특징(최대 토큰, 컨텍스트 크기 등)이 함께 표시됩니다.
- **모델 적용**: 버튼을 클릭하여 챗봇에 해당 모델을 즉시 적용합니다.

### 🔧 고급 설정

- **검색할 문서 개수 (k)**: 답변 생성 시 참고할 문서 청크의 개수를 조절합니다.
- **LLM Temperature**: 모델의 창의성/일관성을 조절합니다. (0.0: 일관적, 1.0: 창의적)
- **🚀 실시간 답변 (스트리밍)**: 답변을 실시간으로 표시할지 여부를 선택합니다.
- **🐛 디버그 모드**: 활성화 시, 답변 생성에 사용된 검색 결과와 점수 등 상세 정보를 표시합니다.

## 💡 RAG 시스템 개선 사항

이 시스템은 정확하고 상세한 답변을 제공하기 위해 다음과 같은 기술적 개선 사항들을 포함하고 있습니다.

#### 1. 프롬프트 엔지니어링
- "쉽게 설명"하는 초기 프롬프트에서 "상세하고 정확한 정보를 빠짐없이 제공"하도록 프롬프트를 개선하여 답변의 깊이를 더했습니다.
- 한자 및 전문 용어에 대한 쉬운 설명을 의무화하여 비전문가도 이해하기 쉽도록 했습니다.

#### 2. 컨텍스트 및 청킹 전략
- **컨텍스트 확장**: LLM에 전달되는 최대 컨텍스트 길이를 늘려(`4000` -> `8000`자 이상) 더 많은 정보를 참고하도록 했습니다.
- **청크 크기 최적화**: 청크 크기를 늘리고(`800` -> `1200`자) 중첩(overlap) 영역을 확대하여, 문서의 맥락이 끊기지 않도록 개선했습니다.
- **의미 기반 청킹**: 단순히 글자 수로 나누는 대신, 문장의 의미를 파악하여 관련 내용이 하나의 청크에 포함되도록 분할합니다.

#### 3. 쿼리 확장
- 사용자의 질문에서 "몽촌토성", "백제" 등 핵심 키워드를 식별하고, "한성백제", "발굴조사", "토기" 등 연관 검색어를 자동으로 추가하여 관련 문서를 더 효과적으로 찾아냅니다.

#### 4. 동적 모델 최적화
- 각 LLM(GPT-4, Gemini 1.5, Claude 3.5 등)이 가진 고유의 최대 토큰 수와 컨텍스트 윈도우 크기를 자동으로 감지합니다.
- 이를 통해 모델의 성능을 최대한 활용하면서도 토큰 제한 오류가 발생하지 않도록 안정성을 확보했습니다.

#### 5. 벡터 DB 품질 관리
- **최소 청크 크기 강화**: 50자 미만의 의미 없는 짧은 청크(예: 목차 제목)가 DB에 저장되지 않도록 최소 크기를 300자로 상향 조정했습니다.
- **짧은 청크 병합**: 너무 짧게 분리된 청크들을 주변 청크와 자동으로 병합하여 의미 있는 단위로 만듭니다. 이를 통해 검색 결과의 품질을 대폭 향상시켰습니다.

## 🏗️ 아키텍처

```
1. 사용자 입력 (Streamlit UI)
   |
   v
2. 쿼리 확장 (RAGChain)
   - "몽촌토성" -> "몽촌토성 백제 한성 왕성..."
   |
   v
3. 벡터 검색 (VectorDatabase: FAISS/Chroma)
   - 확장된 쿼리로 벡터 DB에서 관련 문서 청크 검색
   |
   v
4. 컨텍스트 생성 및 최적화 (RAGChain)
   - 검색된 문서를 모델의 컨텍스트 길이에 맞게 조합
   - 동적 컨텍스트 길이 적용
   |
   v
5. LLM 호출 (RAGChain -> OpenAI/Google/Claude/Local)
   - 프롬프트 + 컨텍스트 + 질문을 LLM에 전달
   |
   v
6. 답변 생성 및 스트리밍
   - LLM이 생성한 답변을 실시간으로 UI에 표시
   |
   v
7. 후처리 (app.py)
   - 답변과 함께 참고 문서, 관련 이미지 표시
```
